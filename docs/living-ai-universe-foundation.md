# TRYAMM Living AI Universe Foundation

Status: DESIGN / IMPLEMENTATION CONTRACT
Target: Birthday Alpha, October 2, 2026

## Product thesis
13 Living Games. One Living Universe. One Identity. One AI.

TRYAMM is designed as a phone-first persistent universe connecting play, creation, learning, work, business, communication and eligible earning pathways. Headsets are optional.

## Flagship proof loop
PASSPORT -> STREETVERSE CHICAGO -> BENNY / HOLOGPT -> MISSION -> XP -> BUSINESS / AAU -> GAMEVERSE -> REEL -> PERSISTENT PROGRESS

The birthday alpha should prove this loop once, end to end, before expanding all 13 games.

AAU is an education platform/program environment unless and until accreditation, degree-granting authority, state approval or institutional partnerships are independently obtained and verified. It must not present completion records as accredited degrees or professional licenses without verified authority.

## Living Universe connective tissue
The universe should share a privacy-respecting Passport for identity, permitted progression, achievements, reputation, accessibility preferences and eligible inventory. Money/accounting remains separate and server-authoritative.

## Universe Event System
A single fictional or approved event may create coordinated experiences across multiple destinations. Example: a major fictional Chicago storm can produce rescue missions in StreetVerse, wet-road racing challenges, logistics/business missions, AAU science lessons, AI Cafe exercises, LIVE coverage, creator challenges and GameVerse unlocks.

Events must have:
- canonical event ID and lifecycle
- world-specific adapters
- start/end/rollback controls
- content and safety review
- accessibility variants
- economy/reward limits
- deterministic critical mission state
- replay/audit evidence

## Stubbs AI / HoloGPT role
Stubbs AI is the orchestration/control plane. HoloGPT/Benny is the embodied user-facing intelligence. The system may plan and propose experiences, but production-changing actions require evidence and release controls.

Tri-Brain roles:
1. Reasoning / Game Director: plan missions, difficulty, narrative and world effects.
2. Builder / Action Brain: assemble candidate code, configuration, assets and workflows.
3. Guardian / Judge: independently verify tests, safety, accessibility, economy integrity and evidence.

## Self-healing and evolution
Use:
OBSERVE -> DIAGNOSE -> REPAIR CANDIDATE -> SANDBOX -> TEST -> VERIFY -> CANARY -> PROMOTE OR ROLLBACK.

AI may create candidates. AI may not certify itself. Security, privacy, financial, human-approval and rollback controls remain outside the self-modifiable plane.

## Game evolution
PLAYER TELEMETRY -> OPPORTUNITY -> CANDIDATE MISSION/LEVEL -> SIMULATED PLAYERS -> ACCESSIBILITY TESTS -> PERFORMANCE TESTS -> HUMAN PLAYTEST -> CANARY -> METRICS -> PROMOTE/ROLLBACK.

No silent production rewriting.

## Creator flywheel
AAU / AI Cafe -> learn -> Holo Game Lab -> build -> test -> portfolio -> publish eligible original content -> creator opportunity -> improve.

Future creator tooling should enable original worlds and experiences without requiring the TRYAMM core team to author everything.

## Device strategy
Phone first -> browser/PWA -> desktop/PC -> TV -> optional AR/VR/MR -> compatible spatial/holographic displays.

One-hand, voice, captions, reduced motion and simplified A/B/C controls are first-class acceptance criteria.

## Release truth
Every capability must be labeled with one of:
DESIGN -> VERTICAL SLICE -> ALPHA -> BETA -> RELEASE CANDIDATE -> CERTIFIED -> LIVE.

Calendar dates never override certification. Preview-ready is not production-live. A feature is not complete until evidence verifies its route, behavior and required integrations.
