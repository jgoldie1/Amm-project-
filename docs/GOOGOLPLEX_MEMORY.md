# Googolplex Memory™

Googolplex Memory is TryAMM's original governed memory architecture. The name is not an affiliation with Google or the Googleplex campus.

## Purpose

Give AMM Intelligence, NPCs, games, creators, call-center agents, arena services and marketplace assistants persistent context without letting memory become uncontrolled surveillance or unverified truth.

## Memory tiers

- Working: current conversation and immediate task state.
- Episodic: dated events and interactions.
- Semantic: approved facts and knowledge.
- Procedural: how to complete a task.
- Relational: links among people, projects, characters, products and events.
- Project: milestones, decisions, files and unresolved work.
- NPC: player-specific lore, trust and recent interactions.
- Arena: ratings, match history, sanctions and replay references.
- Commerce: preferences, wishlists and consented shopping context.

## Lifecycle

1. Ingest only with a purpose and owner.
2. Redact secrets and sensitive raw data.
3. Attach source identifiers, confidence and consent.
4. Link related memories.
5. Retrieve by owner, purpose, tier and visibility.
6. Revise stale facts rather than silently overwriting history.
7. Expire low-value memories.
8. Allow the owner to view, edit, export and forget.

## What it enables

- AMM Intelligence remembers approved preferences and projects.
- NPCs remember player choices and relationships.
- The Arena remembers ratings, matches and moderation outcomes.
- Creators can resume scripts, songs, DAW sessions and production plans.
- Marketplace assistants can remember wishlists and sizes only with consent.
- Call-center agents can continue cases without repeatedly asking the same questions.
- Twin Earth can remember safe locations, portals and progress without exposing private coordinates.
- Cross-device continuity can move from mobile to TV, laptop, VR/MR and the future Volcano console.

## Database

The Supabase migration adds `ai_memories` and `ai_memory_links`, full-text indexes, optional vector embeddings and row-level security.

## Production completion gate

- Apply migrations to a real Supabase project.
- Add authenticated memory APIs.
- Add secret and PII redaction before writes.
- Add embedding generation and hybrid retrieval.
- Add revision, expiration, export and deletion jobs.
- Add user-facing memory controls.
- Add evaluation tests for stale, conflicting and malicious memories.
- Add cost, latency and storage limits.
- Add audit logging and administrator review for shared/public memories.

## Safety rules

Never store passwords, API keys, full payment credentials, raw government IDs, raw biometric templates or precise sensitive locations. Faith memories must separate Scripture, interpretation and fictional storytelling. NPC memory cannot impersonate real people or override server-authoritative game rules.
