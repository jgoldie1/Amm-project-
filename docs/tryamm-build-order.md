# TryAMM Unified Build Order

## Phase 0 — Audit before rewriting
1. Inventory current frontend, backend, database, AI, streaming and deployment code.
2. Mark every registry feature as working, partial, missing or blocked.
3. Do not replace working systems without a regression-tested migration plan.

## Phase 1 — Foundations
- Identity, roles and age-lane policy
- Creator profiles and Omniverse Passport base
- Unified Value Ledger and immutable audit events
- Revenue Waterfall and idempotent settlement service
- Observability, secrets, RLS and authorization review

## Phase 2 — Creator Success
- Qualified Hours Engine
- Protected Break Mode
- 15/30/40 milestones
- Creator Progress Meter
- Agencies / Families
- New on TryAMM / Welcome Train / Rising

## Phase 3 — AI Control Tower
- HoloGPT
- HoloRouter
- Agent Manager
- Cost Manager / HoloCFO
- Trial allowances and HoloGPT Credits
- HoloLingo
- HoloVibe
- HoloGuardian
- HoloAccess
- HoloMatch
- GrowthOS

## Phase 4 — Economy
- Creator Earnings
- Coins
- HoloGPT Credits
- Beans
- XP
- Agency / seller / developer attribution
- Payout and refund workflows

## Phase 5 — Living Worlds + Development Support
- 11 Living Worlds hub
- Follow / Wishlist / Beta Signup
- Support Developer badge system
- Development milestones and transparent support ledger

## Phase 6 — Scale
- Event-driven services where justified by load
- CDN/object storage/caching/queues
- Load and cost tests at 1K, 10K, 100K and 1M scenarios
- Growth funnel instrumentation
- HoloOps incident automation with human approval gates

## Release rule
AI may build, test and prepare pull requests. Production-affecting financial, security, database, moderation and provider-spend changes require explicit review/approval.
