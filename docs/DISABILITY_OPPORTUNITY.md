# TRYAMM Disability Opportunity

Status: LOCKED PRODUCT SPECIFICATION

## Mission
Disability Opportunity is a first-class TRYAMM pathway for disabled people to learn, create, work, start businesses, play, communicate, find accessible services/opportunities, mentor others and build ownership. Accessibility is also a horizontal platform requirement: users do not have to enter a separate disability area to receive an accessible TRYAMM experience.

## Accessibility Passport
Voluntary, user-controlled capability/preferences profile. It is not a medical record and does not require diagnosis.

Possible preferences:
- screen reader/semantic navigation
- keyboard-only
- switch access
- voice control
- one-handed mode / remappable controls
- large touch targets/text
- high contrast
- reduced motion/flashing
- captions/live captions
- transcripts
- audio description
- text-to-speech/speech-to-text
- simplified/cognitive-support presentation
- additional processing time where appropriate
- communication preference
- sensory preferences

Default rule: disclose the minimum information needed. Employers, creators and other users never receive disability information merely because accessibility settings are enabled.

## Opportunity Profile
Users may choose skills, goals, schedule, remote/on-site preference, transportation constraints, accommodation preferences and industries. Do not infer diagnosis or disability from usage.

### Opportunity types

- grants/scholarships
- Academy/trade programs
- mentorship

- sports/esports/gaming
- community leadership/service

## Employer / program accessibility card
Listings can publish structured facts rather than vague `inclusive` labels:
- remote/hybrid/on-site
- step-free/wheelchair access where known
- accessible restroom/parking/transit information where provided
- flexible scheduling
- adaptive equipment availability
- captioning/interpreting process
- communication alternatives
- accommodation request contact/process
- essential job functions
- physical/sensory requirements stated neutrally

Users can report inaccurate accessibility information. Verification state must be visible.

## Accessibility Match
Matching uses user-selected requirements only. Results explain the match:
`REMOTE ✓ | FLEXIBLE SCHEDULE ✓ | VOICE-FIRST WORKFLOW ✓ | CAPTIONING AVAILABLE ✓`.

Never reduce ranking because a person enabled an accessibility setting. Never sell or use accessibility/crisis data for targeted advertising.

## Stubbs AI Accessibility Navigator
Natural-language examples:
- `I can only use one hand. Show jobs and tools I can operate.`
- `I need captions for every class.`
- `Make this game playable without rapid button presses.`
- `Find remote creator work.`
- `Read this screen to me.`

The Navigator converts requests into reversible interface preferences and opportunity filters. It must ask before sharing accommodation information with a third party.

## Creator accessibility
Creator Studio supports captions/transcripts, alt text, audio-description tracks/notes, accessible thumbnails/text, content warnings where appropriate and accessibility preview. Creators can receive an Accessibility Ready checklist without claiming formal certification unless a recognized certification process exists.

## Accessible games
- remappable controls
- one-handed presets
- keyboard/controller/switch/voice abstraction where technically supported
- hold/toggle alternatives
- adjustable timing/difficulty where gameplay permits
- subtitle/caption controls
- visual/audio cue alternatives
- reduced flashing/motion
- color-independent indicators
- menu narration hooks
- pause/single-player assistance where appropriate
- accessibility metadata per game

Competitive modes may preserve fair-play constraints while still providing reasonable accessibility options.

## Academy
Every course template requires accessible structure, captions/transcripts for authored video/audio, keyboard navigation, meaningful headings/labels, alternative text for instructional images and non-color-only meaning. Learning Passport records mastery, not disability.

## LIVE / Soul Ascension / Broadcasting
Support authored/live captions where available, transcript/replay, accessible chat, keyboard controls, readable focus states, reduced-animation mode and audio-description-compatible production workflows. Sign-language/interpreter video tracks can be supported where provided; do not falsely claim automatic sign-language translation is perfect.

## Disability Creator & Business Spotlight
Community Spotlight may feature disabled creators, entrepreneurs, students, athletes, mentors and innovators based on consent and accomplishment. Avoid inspiration-porn framing; spotlight the work, talent, business, service and person.

## Assistive Technology Exchange
Marketplace discovery for legitimate accessibility products/services, repair, training and custom adaptation. Product safety and regulated medical-device claims require appropriate controls. Creator/maker projects must distinguish prototypes from certified medical devices.

## Emergency and resource navigation
Disability Opportunity links to Emergency Path without exposing the user's disability publicly. Resource navigation can include accessible shelter/transportation/contact methods when verified. Imminent-danger handling follows Emergency Path policy.

## Funding alerts
Opportunity Alert Engine can match disability-related grants/scholarships/programs only from facts the user explicitly provides. Display eligibility source, deadline, required proof, geography, last-verified date and `LIKELY/POSSIBLE/VERIFY/NOT A MATCH`; never guarantee funding.

## Community Gap Finder integration
Aggregate unmet accessibility demand can identify gaps such as accessible transportation, captioning/interpreting capacity, adaptive equipment, accessible housing-resource navigation, remote jobs, assistive-tech repair or accessible entertainment. Never expose an individual's help request as evidence.

## Accessibility QA gates
Before PUBLIC release of a core flow:
1. keyboard-only completion;
2. screen-reader semantic review;
3. visible focus and logical focus order;
4. touch-target review;
5. zoom/text-scaling review;
6. contrast/non-color-only review;
7. reduced-motion/flashing review;
8. captions/transcript checks for authored media;
9. form errors announced/explained;
10. one-handed/remappable control review where relevant;
11. mobile orientation/device testing where applicable;
12. disabled-user testing whenever feasible.

Target current WCAG 2.2 AA practices for web interfaces while recognizing that legal requirements vary by product, jurisdiction and context.

## Success metrics
Measure outcomes with privacy safeguards: accessible opportunities published, applications, hires/gigs, courses completed, creator projects published, businesses/suppliers onboarded, accessibility issues resolved, time-to-resolution, user-reported accessibility satisfaction and gaps closed. Do not rank a person's worth or access to basic platform functions by these metrics.
