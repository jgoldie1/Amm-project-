# TRYAMM AbilityWorks + Funding Stack Architecture

**Status: LOCKED ARCHITECTURE / IMPLEMENTATION BUILDING**

This document defines the TRYAMM LLC national cross-disability workforce, education, community-impact, employer and funding program. It extends the existing LearnVerse + Workforce architecture and does not claim that services are LIVE until they are implemented, tested, deployed and manually verified in production.

## 1. Operating Structure

TRYAMM LLC -> National Community Impact & Workforce Division -> AbilityWorks + Funding Stack + Government Solutions + MiddleVerse Jobs + Business Network + AbilityWorks Academy + Inclusive Employer Network + Community Impact Ledger + Command Nexus.

## 2. Participant Path

ACCESS -> ABILITY PASSPORT -> ACCESSIBILITY PREFERENCES -> TRAINING -> COMPETENCY -> CREDENTIAL -> JOB / REMOTE WORK / ENTREPRENEURSHIP -> VERIFIED OUTCOME -> RETENTION -> ECONOMIC IMPACT.

Participant-facing services should default to $0 where an eligible third-party payer or sponsor funds the service. TRYAMM must not make vulnerable participants the primary revenue source for sponsored workforce programs.

## 3. Cross-Disability Scope

The program is designed for broad disability inclusion, including physical/mobility, blind/low vision, Deaf/hard-of-hearing, speech/communication, intellectual/developmental, neurodivergent, chronic-condition-related and other qualifying disability needs.

Product requirements include screen-reader support, keyboard/switch navigation, captions/transcripts, text-to-speech, speech-to-text, reduced motion, high contrast, large targets, one-hand modes, plain language, translation/localization and accessible remote-work workflows.

## 4. Ability Passport

Store only information required for a service. Separate sensitive disability/accommodation data from ordinary employer-facing profile data. Employer-visible fields should be user-selected and authorized.

Possible fields:
- identity/account state;
- preferred communication method;
- accessibility settings;
- assistive technology needs;
- training interests;
- skills and competencies;
- credentials;
- remote/hybrid/on-site preference;
- availability;
- employer-visible evidence selected by user;
- accommodation workflow state where lawfully required.

## 8. Funding Stack

TRYAMM should combine lawful funding layers rather than depend on one grant:
1. government workforce funding;
2. state vocational rehabilitation partnerships/contracts where authorized;
3. education partnerships;
4. employer-paid workforce programs;
5. corporate sponsorship;
6. foundations/philanthropy;
7. government prime/subcontracting;
8. TRYAMM commercial services and SaaS.

Funding states must be explicit: ELIGIBLE / POSSIBLE MATCH / PARTNER REQUIRED / APPLICATION OPEN / APPLIED / AWARDED. Finding an opportunity is never equivalent to receiving funding.

## 13. Community Impact Ledger

Track only verified and authorized aggregate outcomes:
- participants enrolled;
- training completions;
- competencies mastered;
- credentials earned;
- interviews/referrals;
- verified placements;
- 90/180/365-day retention;
- businesses launched;
- businesses hiring graduates;
- wages/contract income;
- sponsored training dollars;
- government/employer program revenue.

Blockchain or hash-based verification may supplement audit trails, but conventional accounting/financial systems remain authoritative for regulated award and contract accounting.

## 14. Revenue Flywheel

COMMUNITY -> TRAINING -> VERIFIED SKILL -> JOB / BUSINESS -> INCOME -> EMPLOYER / MERCHANT -> MORE JOBS -> GOVERNMENT / CORPORATE PARTNERS -> MORE PROGRAM FUNDING -> MORE PARTICIPANTS.

TRYAMM earns through legitimate deliverables: workforce contracts, employer services, technology/SaaS, implementation, Funding Stack services, licensing, education partnerships, sponsorship programs and approved government subcontracting.

## 16. Production Definition

A capability becomes LIVE only after:
1. code exists;
2. automated checks pass;
3. accessibility/security review is complete for the feature;
4. production deployment succeeds;
5. real user flow is manually verified;
6. monitoring/rollback is available;
7. Founder Command Center status is updated truthfully.
