# CLAUDE.md — TRYAMM Build Instructions

## Mission
Build TRYAMM as one coherent platform, not disconnected demos or modal hubs.

## Canonical UX
HOME | PLAY | LIVE | CREATE | NEXUS

All work strengthens:
JOIN → DISCOVER → LEARN → CREATE → OWN → PUBLISH → PLAY/WATCH/LISTEN → COMMUNITY → EARN → GET PAID → ACHIEVE → RECOGNITION → LEGACY.

## Non-negotiable architecture
1. One account/user identity across every module.
2. Algorithm Router chooses specialized ranking systems by intent.
3. Algorithm Studio lets users build algorithms via sliders, visual rules or natural language; algorithms can be saved/shared/remixed. Custom ranking never bypasses platform safety, age, copyright, fraud or jurisdiction rules.
4. All American Passport stores TRYAMM achievements/credentials/reputation; never represent it as a government passport.
5. All American Wallet is a UI over Money Engine balances and transaction states; never treat creator liabilities as TRYAMM operating cash.
6. Creator Project is the parent object for related media/products/worlds and their rights metadata.
7. Rights agreements are versioned; accepted splits must be deterministic and auditable.
8. Money Engine uses balanced double-entry accounting and sandbox-first payment integration.
9. Real payouts and regulated money functions remain OFF until launch gates pass.
10. Accessibility, moderation, security, search, analytics, notifications, backups and admin observability are horizontal requirements.

## Product pillars
Creator Studio; Academy; Reels/Stories; movies/anime; music/Set Apart; LIVE; games; AR/VR/MR/holographic creation; Omni Box; Marketplace/Talent Exchange; Opportunities; Rights/Distribution; Wallet/Passport; charts/certifications; awards/Hall of Fame; Family/Legacy.

## Awards and legacy
Maintain the Kenosha Stubbs Legacy Award as a living-honor/service award celebrating compassion, family, community and licensed social-work service. Keep service awards distinct from popularity metrics.

## Development rules
- Prefer integration/completion over new top-level features.
- Never mark simulated, mocked, sandbox, undeployed or unlicensed capabilities production-ready.
- Never weaken Supabase RLS or expose service-role credentials to clients.
- Payment/webhook operations must be server-side, authenticated, idempotent and auditable.
- Money amounts use integer minor units; percentage splits use basis points.
- Game/promotional credits must be visibly distinct from withdrawable money.
- Preserve backwards compatibility where practical while migrating older hubs into canonical UX.
- Add tests for financial allocation, rounding, authorization and state transitions when supported by the repo test stack.

## Definition of done
A new user can join, understand the interface, discover relevant content, create/play something, save progress, interact safely and return later. Monetized flows are done only when ledger, rights, reconciliation, refund/dispute and payout states are verifiably correct.
